# CSS Architecture

## How it actually works

The app never loads individual CSS files at runtime — `client/pages/index.html` links exactly one stylesheet, `client/styles/bundled.css`. That file is generated by `build-css.js`, which concatenates the real source files in a fixed order and writes the result. **After editing any source `.css` file, run `node build-css.js` to regenerate the bundle** — editing `bundled.css` directly will be overwritten on the next build.

## Source files, in bundle order

```
styles/core/variables.css        design tokens (spacing, radii, z-index, etc.)
styles/core/reset.css            browser reset
styles/core/colors.css           color tokens (light/dark theme variables)
styles/core/typography.css       font stacks, type scale
styles/legacy/main.css           core layout: grid, sidebar, player controls, now-playing
styles/legacy/components.css     largest file: notifications, badges, search, library grid,
                                  playlist UI, modals, dual-pane layout
styles/legacy/favorites.css      favorites & recently-played views
styles/legacy/folder-browser.css folder tree / file browser panel
styles/layout/grid.css           top-level page grid
styles/layout/header.css         header bar, logo
styles/layout/sidebar.css        sidebar nav
styles/layout/footer.css         player footer / visualizer container
styles/components/buttons.css    button variants
styles/components/cards.css      song/album/artist cards
styles/components/forms.css      inputs, selects
styles/components/states.css     loading/empty/error states
styles/features/player.css       playback controls, progress bar
styles/features/modals.css       modal overlay system
styles/features/notifications.css toast notifications
styles/features/search.css       search input & results
styles/utilities/utilities.css   helper classes (line-clamp, spacing, etc.)
help/help.css                    in-app help viewer
styles/fixes/modal-interaction-fix.css  targeted override, applied last
```

**Note on the `legacy/` folder name**: despite the name, `legacy/main.css` and `legacy/components.css` are the two largest, most load-bearing files in the bundle — they are *not* dead code, they're just named for an earlier CSS reorganization that never finished renaming them. Don't delete anything in `legacy/` without checking `build-css.js`'s file list first.

## Loading order matters

`core/variables.css` and `core/colors.css` define the CSS custom properties (`--primary`, `--surface`, `--text-primary`, `--border`, etc.) that every later file depends on — they must stay first in `build-css.js`'s list. `styles/fixes/modal-interaction-fix.css` is intentionally last so it can override anything above it.

## Known dead weight

- `client/styles/legacy/folder-browser.old` — not referenced in `build-css.js`'s file list, not loaded anywhere. Confirmed dead; removed as part of the 2026-09-11 cleanup.

## Responsive breakpoints

- `1400px+` — full desktop layout
- `1200px` — reduced sidebar width
- `768px` — single-column, stacked dual-pane layout
- `480px` — mobile-optimized spacing

## Theming

Light/dark theme is driven entirely by CSS custom properties in `core/colors.css`, toggled via a `[data-theme="dark"]` attribute on the root element. `ui-controller.js`'s `toggleTheme()` flips the attribute and also reloads the theme-appropriate header logo (see `docs/application/architecture.md`).
